# 설계 문서: 회의 목록 페이지 (검색 + 페이지네이션)

- 생성일: 2026-08-23
- 프로젝트: Meeting Junior
- 작성자: Claude (AI) — product-manager 에이전트
- 상태: 승인됨
- 관련 기능: 회의 목록 탐색, 제목/요약 검색, 페이지 번호 네비게이션

---

## 1. 배경 및 목적

회의록이 누적될수록 현재의 사이드바 목록만으로는 탐색이 어렵다. 빠른 전환(최근 회의 바로 접근)과 브라우징(과거 회의 내용 탐색) 두 패턴을 모두 지원하는 전용 목록 페이지가 필요하다.

---

## 2. 범위

### 포함
- `/meetings` 경로의 독립 목록 페이지
- 제목 + 요약 대상 텍스트 검색 (300ms debounce)
- 페이지 번호 기반 페이지네이션 (12개/페이지)
- URL 상태 연동 (`?q=...&page=...`)
- 사이드바에 "전체 목록 보기" 링크 추가

### 제외 (1차)
- 날짜 범위 필터, 상태 필터, 정렬 옵션
- 검색어 하이라이트
- 무한 스크롤
- transcript(전체 대화) 검색

---

## 3. 라우팅 구조

```
/            → 기존 뷰 (녹음 + 처리 + 결과) — 변경 없음
/meetings    → 신규 목록 페이지
/?job=<id>   → 기존 뷰에서 특정 회의 선택 (기존 + 파라미터 처리 추가)
```

네비게이션 흐름:
1. 사이드바 "전체 목록 보기" 클릭 → `/meetings`
2. 목록 카드 클릭 → `/?job=<id>` (해당 회의 자동 선택)
3. `/meetings` 헤더 "돌아가기" 클릭 → `/`

## 4. UI 명세

### 4-1. 레이아웃

```
┌─────────────────────────────────────────────────────────┐
│  ← 돌아가기          Meeting Jr. — 회의 목록             │
├─────────────────────────────────────────────────────────┤
│  [🔍 회의 제목 또는 내용으로 검색...               ]     │
│                          총 47건 · 5페이지 중 1페이지    │
├──────────────┬──────────────┬──────────────┬────────────┤
│  MeetingCard │  MeetingCard │  MeetingCard │ MeetingCard│
│      ...     │      ...     │      ...     │     ...    │
├──────────────┴──────────────┴──────────────┴────────────┤
│              [←]  [1]  [2]  [3]  ...  [5]  [→]         │
└─────────────────────────────────────────────────────────┘
```

- 데스크탑: 4열 그리드
- 태블릿: 2열
- 모바일: 1열

### 4-2. MeetingCard 표시 정보

| 항목 | 출처 | 비고 |
|------|------|------|
| 회의 제목 | `job.title` | 읽기 전용 |
| 날짜 | `job.created_at` | YYYY-MM-DD 형식 |
| 녹음 시간 | `job.duration_sec` | "N분" 형식, 없으면 미표시 |
| 참석자 | `job.speakers` 값 목록 | 최대 3명 + "외 N명" |
| 요약 미리보기 | `job.summary` 첫 100자 | 없으면 "요약 없음" |
| 액션 아이템 수 | summary에서 `- [ ]` 패턴 카운트 | 0이면 미표시 |
| 상태 뱃지 | `job.status` | done=초록, 처리중=파랑, error=빨강 |

### 4-3. Pagination 컴포넌트 동작

```
총 페이지 1개  → 페이지 번호 숨김
현재 페이지 앞뒤 2개 항상 표시
첫 페이지 / 끝 페이지 항상 표시
중간 생략 시 ... 처리

예) 현재 5페이지, 총 10페이지:
[←]  [1]  ...  [3]  [4]  [5]  [6]  [7]  ...  [10]  [→]
```

- `[←]` / `[→]`: 첫/끝 페이지에서 비활성화(disabled)
- 클릭 시 URL searchParams 업데이트 (`router.push`)

### 4-4. 검색 동작

- 입력 후 300ms debounce → 자동 검색 (검색 버튼 없음)
- 검색어 변경 시 page=1 으로 자동 리셋
- 결과 0건: "검색 결과가 없습니다" + 검색어 초기화 버튼
- 검색 중 로딩 스피너 표시

## 5. 백엔드 명세

### 5-1. 신규 엔드포인트

```
GET /api/meetings?q=&page=1&limit=12
```

**쿼리 파라미터:**
| 파라미터 | 타입 | 기본값 | 설명 |
|----------|------|--------|------|
| q | string | "" | 검색어 (빈 문자열 = 전체) |
| page | int | 1 | 페이지 번호 (1-based) |
| limit | int | 12 | 페이지당 개수 (고정) |

**응답 형식:**
```json
{
  "items": [ /* Job 배열 */ ],
  "total": 47,
  "page": 1,
  "pages": 4
}
```

**SQL 쿼리:**
```sql
-- 검색어 있을 때
SELECT * FROM meetings
WHERE (title LIKE '%?%' OR summary LIKE '%?%')
ORDER BY created_at DESC
LIMIT 12 OFFSET (page-1)*12

-- 전체 건수
SELECT COUNT(*) FROM meetings
WHERE (title LIKE '%?%' OR summary LIKE '%?%')
```

- 기존 `GET /api/jobs` 엔드포인트는 변경 없음 (사이드바 폴링에 계속 사용)

### 5-2. 신규 DB 함수

```python
# database.py에 추가
def search_jobs(q: str, page: int, limit: int = 12) -> dict:
    """
    제목 + 요약 LIKE 검색 + 페이지네이션.
    반환: {"items": [...], "total": N, "page": N, "pages": N}
    """
```
