## 목표

현재 "회의록 생성" 앱을 **범용 음성 → 문서 정리 플랫폼**으로 확장한다.
사용자가 카테고리(회의록·강의노트·설교요약 등)를 선택하면 해당 카테고리에 맞는 Claude 프롬프트로 문서를 생성한다.
설정 화면에서 카테고리를 관리(추가·수정)하고, 각 카테고리는 기본 프롬프트를 보유한다.

## 1. 데이터 모델

### 1-1. categories 테이블 (신규)

```sql
CREATE TABLE IF NOT EXISTS categories (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  icon        TEXT NOT NULL DEFAULT '📋',
  description TEXT NOT NULL DEFAULT '',
  prompt      TEXT NOT NULL,
  is_builtin  INTEGER NOT NULL DEFAULT 0,
  sort_order  INTEGER NOT NULL DEFAULT 99,
  created_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
```

| 컬럼 | 설명 |
|------|------|
| id | UUID (내장 카테고리는 고정 slug: "meeting", "lecture", "sermon", "interview", "brainstorm") |
| name | 표시 이름 |
| icon | 이모지 아이콘 |
| description | 용도 설명 (드롭다운 부제목용) |
| prompt | `{script}` 플레이스홀더 포함 Claude 프롬프트 |
| is_builtin | 1=기본제공(삭제 불가), 0=사용자 생성 |
| sort_order | 목록 표시 순서 (내장: 1~5, 사용자: 10~) |

### 1-2. jobs 테이블 변경

```sql
ALTER TABLE jobs ADD COLUMN category_id TEXT REFERENCES categories(id);
```

- NULL = 회의록 카테고리 폴백 (기존 데이터 하위 호환)

### 3-3. Notion 변환 규칙 (notion_sync.py 적용)

프롬프트 출력이 아래 마크다운 → Notion 블록으로 자동 변환된다.

| 마크다운 | Notion 블록 타입 |
|---------|----------------|
| `# 텍스트` | `heading_1` |
| `## 텍스트` | `heading_2` |
| `### 텍스트` | `heading_3` |
| `- 텍스트` | `bulleted_list_item` |
| `1. 텍스트` | `numbered_list_item` |
| `- [ ] 텍스트` | `to_do` (checked: false) |
| `> 텍스트` | `quote` |
| `` `텍스트` `` | `code` (inline) |
| `│표│` | `table` |
| `**볼드**` | bold annotation |

→ 현재 notion_sync.py의 마크다운 파서가 이 규칙을 지원해야 한다.
→ `표(│)` 변환은 신규 구현 필요 (현재 미지원). **구현 범위에 포함.**

## 4. API 엔드포인트

### 4-1. 신규

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/categories` | 전체 목록 (sort_order 오름차순) |
| POST | `/api/categories` | 사용자 카테고리 생성 |
| PATCH | `/api/categories/{id}` | 이름·아이콘·설명·프롬프트 수정 |
| DELETE | `/api/categories/{id}` | 삭제 (is_builtin=1 → 422 거부) |
| POST | `/api/categories/{id}/reset` | 내장 카테고리 프롬프트 DEFAULT 복원 |

### 4-2. 기존 변경

| 엔드포인트 | 변경 |
|-----------|------|
| `POST /api/record` | body: `category_id?: string` 추가 |
| `POST /api/jobs/{id}/finalize` | body: `category_id?: string` 추가 (없으면 job.category_id 사용) |
| `GET /api/jobs/{id}` | 응답: `category_id`, `category_name`, `category_icon` 포함 |
| `GET /api/jobs`, `GET /api/meetings` | 응답 카드에 `category_icon`, `category_name` 포함 |

### 4-3. 요약 로직 우선순위

```
finalize body의 category_id
  → job.category_id (녹음 시 선택값)
    → CLAUDE_PROMPT 설정값 (기존 하위 호환)
      → summarizer.py DEFAULT_PROMPT
```

## 6. UI 상세

### 6-1. RecordingZone — 카테고리 선택

- 녹음 버튼 위에 카테고리 드롭다운 1개
- 초기값: localStorage에 저장된 직전 선택값 (없으면 "회의록")
- 드롭다운 항목: `{icon} {name}` + `{description}` 부제목
- 선택값은 `POST /api/record` body에 `category_id`로 전달

### 6-2. TranscriptEditor — 카테고리 확인·변경

- 헤더 오른쪽 영역: `{icon} {name} ▼` 드롭다운
- "회의록 생성" 클릭 시 현재 선택 카테고리의 `category_id` 포함
- 드롭다운은 `CategorySelect` 공통 컴포넌트 재사용

### 6-3. Done 화면

- 제목 옆: `{icon} {name}` 뱃지 (읽기 전용)
- SummaryPanel의 "재요약" 버튼 클릭 → 카테고리 선택 모달 표시
  - 현재 카테고리 기본 선택
  - 다른 카테고리로 변경 후 재요약 가능
  - "재요약 실행" → `POST /api/jobs/{id}/finalize` body에 `category_id` 포함

### 5-4. 설정 모달 — 카테고리 탭

탭 구성: `[API 키]  [Claude]  [카테고리]`

카테고리 탭:
- 카테고리 목록 (sort_order 순)
- 내장: 삭제 버튼 비활성, 편집 버튼 활성
- 사용자: 편집·삭제 모두 활성
- 하단: `[+ 새 카테고리 추가]` 버튼

편집 패널 (인라인 펼침):
- 이름 입력
- 아이콘 입력 (이모지 텍스트 입력)
- 설명 입력
- 프롬프트 textarea (10행, monospace)
- `[기본값으로 초기화]` 버튼 (내장 카테고리만, 저장하지 않고 textarea 값만 복원)
- `[저장]` 버튼

## 7. DB 마이그레이션 전략

- 앱 시작 시 `init_db()`에서:
  1. `categories` 테이블 생성 (IF NOT EXISTS)
  2. `jobs` 테이블에 `category_id` 컬럼 추가 (ALTER TABLE IF NOT EXISTS 패턴)
  3. 5개 내장 카테고리 시드 — `INSERT OR IGNORE` (기존 데이터 보호, prompt 덮어쓰지 않음)
- 기존 jobs의 `category_id = NULL` → API 응답 시 회의록(meeting) 카테고리 정보로 폴백
